# Release v0.10.0

## Overview

v0.10.0 is a separation release. MCP used to be something the Gateway could do on the side: flag a plugin with
`autoGenerateMcp` and the Gateway started an MCP server in its own process. In 0.10 the two are fully separated. The Gateway
serves HTTP and knows nothing about MCP, and the standalone MCP server reads a Gateway plugin's contract off disk and serves
its routes as tools. The same plugin directory feeds both processes, while neither depends on the other running.

The CLI follows: `mdk run mcp` starts that server for every Gateway plugin declared in `mdk.yaml`.

The release also narrows the agent package to what consumers use, closes two Gateway exposures, and adds a generated
reference page for the monorepo's packages.

## Breaking changes

**The Gateway no longer hosts MCP.** `startGateway()` drops its `mcp` option and the `autoGenerateMcp` flag on
`extraPluginDirs` entries. A stack that relied on the flag gets no tools after upgrading until it starts the standalone
server, with `mdk run mcp` or by passing the same plugin dirs to `createMcpServer()` as `gatewayPluginDirs`. The
`mvp-site` example shows the migration.

**`@tetherto/mdk-mcp` changes its exports.** `startMcpHttpServer` and `generateToolsFromGatewayPlugin` leave the public
surface, `loadGatewayPluginTools` joins it, and the package now depends on `@tetherto/mdk-gateway` rather than the reverse.

**`@tetherto/mdk-agent` exports four names**: `createAgent`, `EVENT`, `isTerminal` and `AgentEventSchema`, down from 37.
An `exports` map also closes deep imports into `src/`.

**Op Centre becomes Op Center in the UI public surface.** Five exported constants and the `hooks.json` category `op-centre`
are respelled with no deprecated aliases. The full list is in [`CHANGELOG.md`](../../../CHANGELOG.md).

## What's new

**`mdk run mcp`** boots the standalone MCP server with every plugin in `spec.gateway.plugins` as a tool source. It listens
on the new optional `spec.mcp.port`, or the Gateway port plus 100, needs the Kernel already running, and is never part of
`mdk run all`.

**Gateway plugins as MCP tools.** `createMcpServer()` takes Gateway plugin dirs beside its native `mcp-plugin.json` ones and
merges both into one tool set. Each plugin gets the context it gets under the Gateway, `onReady` included, and a tool id
declared by two sources fails with both named.

**A package reference page** lists the monorepo's packages by group, with what each is for and whether it is publishable,
generated from the packages themselves.

## Security

**Gateway error messages are masked for real.** The masking ran where Fastify cannot send a reply, so clients received every
thrown message verbatim, internal ones included. Clients now see `ERR_*` codes and Fastify's own 4xx messages, and the status
text for anything else, which is logged instead.

**`?overwriteCache=true` needs an `Authorization` header.** Before, any caller could force a fresh Kernel fetch on every
cached route. The Gateway does not validate the header, so a route whose controller checks no token still needs its own
protection.

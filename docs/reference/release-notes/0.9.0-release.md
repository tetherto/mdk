# Release v0.9.0

## Overview

v0.9.0 is a foundations release. While v0.8.0 provided the operator agent, 0.9 defines how the repository installs,
how a Gateway plugin reports what it is doing, and how a claim about the agent's quality can be checked.

With v0.9.0 the MDK backend becomes **one workspace.** The repository used to be a federation:
`backend/core`, `backend/workers` and `packages` were each their own install root, each with its own lockfile,
kept in step by hand-written shell scripts. They are now members of a single root npm workspace, so one `npm install` hoists and
links everything. The UI toolkit stays separate, with its own lockfile.

Plugins can speak: a Gateway plugin used to have `console` and nothing else — no level, no timestamp, no name. It now
receives a tagged logger on its context, sharing one destination with the Gateway's own request log, plus an `onReady` hook for work
that cannot happen at load time.

Sizing becomes a skill: `mdk-site-sizing` turns a description of a site into a Kernel/Worker/Gateway layout, reading the
benchmark harness's measured envelopes rather than estimating.

## Breaking changes

**The repository installs from the root.** `backend/core`, `backend/workers` and `packages` are no longer separate
install roots with their own lockfiles and shell scripts. A single root `npm install` now hoists and links
everything, and `npm run setup` is the UI workspace plus that root install. A checkout with old nested
`node_modules` directories needs those removed first, since npm resolves against a stale nested tree in preference
to the hoisted one.

**The agent's model stack crosses several majors at once**, including `ai` 6 to 7 and `zod` 3 to 4. A host that
pins these dependencies itself needs to move with them; the full set of versions is in [`CHANGELOG.md`](../../../CHANGELOG.md).

> [!NOTE]
> **`npm ci` still requires the agent to install the agent Gateway plugin.** `@tetherto/mdk-plugin-agent` depends on
> `@tetherto/mdk-agent` as a required dependency, not an optional peer. This is a known limitation carried into
> 0.9.0, not a new regression; tracked as open.

## What's new

**Gateway plugins get a logger and an `onReady` hook**, both frozen onto the context a plugin imports. The logger
is a `pino` instance tagged with the plugin's own name, sharing one destination with the Gateway's own request log;
`onReady` defers work until the server is actually up.

**An evaluation layer for the agent**: a hash-chained run ledger, a reproducibility manifest and a scoring rollup
with a regression gate, so a battery score is attributable to a specific tree, model and charter instead of a bare
number.

**`mdk-site-sizing`** joins the skill suite, turning a plain description of a site into a Kernel/Worker/Gateway
layout using the benchmark harness's measured envelopes.

**Scaffolds link bundled packages by relative `file:` spec** rather than a workspace glob, so a generated project
installs standalone instead of depending on living inside this repository.

Smaller additions: an inline `Loader` variant, a plugin-owned MDK client for scaffolded plugins, and a CI smoke test
that boots a scaffolded plugin behind a real Gateway.

## Removed

**`@tetherto/mdk-ui-cli` (`mdk-ui`)** is gone entirely; `@tetherto/mdk-cli` (`mdk`) remains the supported
command-line entry point. The shell template's System Info page is also removed.

## Fixed

A working agent turn no longer looks frozen while waiting for its first token.

## Security

**A site security blueprint** documents how to secure an enterprise MDK site, starting from what MDK does not
provide: no user identity at any tier, and every plugin route served to any caller.

`undici` is pinned to `>= 6.24.0` at the root, covering every workspace member in one place now that the tree has
a single install root.
